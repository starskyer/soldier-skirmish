# 模拟执行与结算规则

当前实现为单线程 60Hz 固定时间步。模拟核心不依赖 SDL、系统时钟、锁、睡眠或工作线程；窗口控制器负责输入、真实时间与显示。

## 版本与职责

[`v0.1.0-baseline`](https://github.com/starskyer/soldier-skirmish/tree/v0.1.0-baseline) 固定提交 `3170aa7`，保留跨平台迁移与初步修复后的课程版本。当前重构保留格子地形、四方向 BFS、三种兵种和原始素材。

- `Chessboard`：静态地形、基地占地、坐标和有界邻居查询。
- `Soldier` / `Base`：按值保存单位、基地、冷却和计时；单位拥有不复用的 ID。
- `BattleState`：权威单位表及格子占用索引，不在格子里拥有士兵对象。
- `AttackBehavior` / BFS：只读共同快照，产生引用实体 ID 的意图。
- `resolveTurn`：复核合法性、汇总伤害、裁决移动冲突，不修改快照。
- `Model`：提交结果，清理死亡对象、出兵、更新视野并检查状态约束。
- `Controller` / `View`：主线程输入、固定步长累积、插值绘制和 RAII 资源管理。

```mermaid
flowchart LR
    S[本步共同快照] --> P[单位和基地提出意图]
    P --> R[合法性检查与统一裁决]
    R --> D[汇总伤害与死亡]
    D --> M[提交存活单位移动]
    M --> E[判断终局或出兵]
    E --> V[视野与状态约束检查]
    V --> S
```

## 时间与动作

- 一个 tick 为 1/60 秒模拟时间，暂停时不推进 tick、冷却、出兵或随机数状态。
- 步兵、弓箭手每 20 tick 移动一格，攻城炮每 30 tick 移动一格；一般移动周期向上取整到整数 tick。
- 单位攻击冷却 60 tick。一次行动为移动或攻击，不支持移动射击；移动也占用对应的行动间隔。
- 开始后的首个 tick 出兵，其后按 `BASE_GENTIME` 周期尝试；出生点被占据时跳过本次，下一周期再试，不覆盖单位。
- 新单位最早在下一 tick 行动。单位 ID 只增长，不因死亡回收复用。
- 控制器最多每帧追赶 8 个 tick，超出积压被丢弃。严重卡顿时模拟相对墙钟变慢，避免无限补算；这不会为单个单位额外执行动作。
- GUI 空闲时使用 SDL 事件等待，不用空循环轮询。核心中没有需要 notify 唤醒的模拟线程。

## 共同快照和结算

所有本步意图读取同一份单位、位置、生命值和占用状态。单位遍历顺序不直接修改其他单位的决策输入。

1. 校验每个行动者唯一性、起点身份、冷却及目标合法性，拒绝重复或过期意图。
2. 移动只申请快照中为空的四邻接地面。按目标格汇总竞争，等待移动时间更长者优先；相同时对按 ID 排序的候选者进行固定种子裁决。
3. 攻击按目标 ID 校验敌我关系、存活、距离和伤害类型，汇总全部有效伤害。
4. 扣血并移除死亡单位。已经成立的攻击仍生效，允许同时击杀；死亡单位的移动不提交。
5. 提交存活获胜者的移动。若获胜者本步阵亡，不在同一步递补另一候选者。
6. 任一基地归零则结束，双方同时归零判平局。终局不再出兵；否则在更新后的空出生点尝试生成单位。

等待移动时间只在实际申请移动或无路等待时积累，成功移动后清零；攻击或尚未到行动时刻不积累争格优先级。

当前保守策略不允许交换格子、穿过本步将腾空的格子或环形换位。它确保占用一致，但不是完整的群体拥堵解决方案。

## 攻击、视野与基地

- 伤害是否成立取决于本步快照中的位置；目标同一步移走仍承受已成立伤害，伤害跟随单位 ID，不会转移给后来占格的单位。
- 攻击与视野沿用方形范围，不检查墙体遮挡。攻城炮只攻击建筑；其他兵种优先处理射程内敌兵，其次追踪视野内敌兵，再攻击或接近敌方基地。
- 基地默认反击，保留伤害 50、相对中心的射程 4，冷却 60 tick；优先选择中心距离最近的敌兵，距离相同时选较小 ID。
- 单位攻击基地按到基地占地最近格的距离判断，保持课程版占地射程含义。
- 队伍视野由存活基地和单位的范围合并；模式 0 为双方视野的并集，1/2 为红/蓝队。初始视野在首帧前建立。

## 显示位置与逻辑位置

逻辑落位在该步提交时完成，目标格立即被占用。显示位置在移动持续时间内，从起点向终点插值；暂停保持显示进度，视野和攻击仍使用离散逻辑位置。

这是显示平滑，不是连续空间碰撞。单位会在画面上经过两格之间，但不因此引入浮点寻路、途中碰撞或物理体积。后续连续坐标版本需要单独设计。

窗口按可用屏幕尺寸缩放，使用逻辑画布和 letterbox 处理窗口尺寸变化；鼠标事件先映射到逻辑坐标。结果显示期间主循环仍处理退出，三秒后自动结束。

## 所有权和错误处理

单位、基地、地图和快照使用值对象及标准容器，清理不依赖进程退出。动作中保存实体引用，不长期保存指向其他单位的裸指针。

SDL 窗口、渲染器、纹理、字体和临时 surface 使用 RAII；初始化中途失败会逆序清理。构造函数不进入游戏循环。命令行或资源错误返回非零退出码。

## 验证范围

核心回归检查占格、目标身份、攻击距离、冷却、同刻伤害、死亡后移动、暂停、终局、出兵、视野、输入解析和固定步长。每个模拟步检查单位表与占用索引一致、位置合法、生命值有效。

CI 运行三组固定种子的有界对局，超时未产生结果属于失败，不强制判胜。Linux 的无窗口核心另运行 ASan、UBSan 和泄漏检查。固定种子及状态指纹用于回归，不构成任意平台、未来版本或任意输入轨迹的兼容承诺。
