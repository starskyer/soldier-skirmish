# 模拟执行与结算规则

状态：后续开发的设计约定，**尚未实现**。当前代码行为及验证范围以 README 为准。

## 开发边界

[`v0.1.0-baseline`](https://github.com/starskyer/soldier-skirmish/tree/v0.1.0-baseline) 固定提交 `3170aa7`，包含课程项目的跨平台迁移与初步修复。后续开发保留自动对战模拟的项目形态，并完善可靠性和展示。

实时性目标是多个单位在同一个模拟时间轴上行动。CPU 计算意图的顺序不应直接决定红蓝队或某个单位的先手优势。

## 执行方案

推荐以固定时间步推进模拟、分离渲染，按共同状态收集意图，再批量结算：

```text
时刻 t 的状态
  → 到行动时刻的单位分别提出意图，读取同一份状态
  → 检查意图合法性并处理移动冲突
  → 按确认后的规则汇总伤害、死亡和出兵
  → 提交下一状态
  → 渲染
```

各单位保留独立的移动速度、攻击冷却与行动时间，并非每个时间步都必须行动。视觉上可以在模拟状态之间插值，模拟频率和显示帧率分别控制。

具体时间步、移动与攻击的相位关系、伤害发生时刻仍需在实施前确定。固定时间步本身不会自动解决这些规则问题。参考：[固定时间步与渲染解耦](https://gafferongames.com/post/fix_your_timestep/)。

## 已确认规则

### 空格竞争

多个单位同时申请同一空格时：

1. 实际等待移动时间较长的单位优先。
2. 等待时间相同时，使用固定随机种子参与裁决，避免长期按队伍或单位编号优先。
3. 裁决失败者本次不能占用目标格；具体重试和重新寻路时机在拥堵策略中确定。

等待时间使用模拟时间；暂停不积累等待，成功移动后清零。固定种子用于复现，裁决还需要稳定的单位标识和候选顺序。跨平台复现结果须经验证。

该规则处理多个单位争抢一个空格，不单独解决友军交换位置、环形等待或路径不可达。

### 同时攻击

同一模拟时间点已经满足攻击条件的攻击统一结算：

- 汇总所有有效伤害后再更新生命值和死亡状态。
- 允许双方同归于尽。
- 不因为先遍历某个单位，就取消对方同一时刻已经成立的攻击。

目标身份、敌我关系、射程和攻击者存活状态须在选定的结算状态下统一校验。移动与攻击并存时使用哪个位置、是否引入弹道或命中延迟，尚未确定。

### 基地反击

基地应攻击进入射程的敌兵，后续默认开启。实现时补齐攻击间隔和合法目标选择，不能直接启用原有无节流的攻击循环。

基线参数为伤害 50、射程 4。攻击周期、射程相对基地中心或占地边缘的计算方式、目标选择及平衡调整仍需明确。

## 修复目标

- 每个存活单位只有一个有效位置，每格最多一个单位，棋盘占用与单位表一致。
- 死亡单位不能继续移动、攻击或重新占格；过期目标不能造成友军误伤。
- 暂停不推进模拟时间，对局结束后停止出兵和伤害，退出能够可靠完成。
- 对象及 SDL 资源有明确所有者，清理不依赖进程退出。
- 无路、拥堵和目标失效有有界处理，不通过无限忙等待解决。

## 后续待确认事项

- 障碍物是否遮挡视野和攻击，三种兵种是否使用相同的遮挡规则。
- 友军是否可以交换格子或通过同时腾出的格子；拥堵时等待、让路和重新规划的边界。
- 同一时间点的移动、攻击、死亡和出兵之间的规则；双方基地同时归零时的结果。
- 速度调节、对局重开与窗口适配的实现范围。

原有三兵种、自动出兵和四邻接 BFS 是首轮修复的保留基础。新增规则与平衡调整分别记录，避免将玩法变更混入纯资源或生命周期修复。
